# 游戏开发指南

本目录只提供开发规范和参考结构，不提供运行时代码。每个游戏在自己的目录内完整实现所需能力，可以复制合适的起点，但复制后独立维护。

## 指南组成

| 文档 | 适用范围 | 内容 |
| --- | --- | --- |
| [普通游戏开发指南](./game-guide.md) | 仓库内所有游戏 | 项目结构、屏幕适配、生命周期、输入、资源和通用工程约束 |
| [FC-like 游戏指南](./fc-like-guide.md) | 明确标记为 FC-like 的游戏 | 固定逻辑画面、像素渲染、时间步、虚拟控制器和复刻验收 |
| [游戏动效、缓动与 UI 设计指南](./motion-ui-guide.md) | 仓库内所有游戏 | 输入反馈、状态变化、界面动效、组件状态和减弱动效 |

普通游戏指南是基础。FC-like 游戏同时遵循普通游戏指南和 FC-like 指南；动效指南横向适用于两类游戏。具体游戏的玩法、规则、物理模型和关卡设计由游戏自身决定，不在本目录统一规定。

## 规范用词

- `必须`、`不得`：影响依赖边界、生命周期、正确性或基本可用性的要求。
- `应该`：默认采用的项目基线，有明确原因时可以偏离。
- `可以`：按项目需要选择的能力或参考实现。

代码示例用于说明结构，不表示每个游戏必须创建完全相同的文件或 API。

## 使用流程

```text
确认游戏形态与目标设备
-> 判断是否为 FC-like
-> 选择最小项目结构
-> 确定屏幕和输入方案
-> 建立资源清单与生命周期
-> 实现游戏自身玩法
-> 按动效指南补齐反馈
-> 完成对应检查
```

## 边界

本指南不统一规定：

- 平台跳跃、俯视射击、棋牌等具体玩法结构。
- 实体、碰撞、伤害、计分和胜负的更新顺序。
- 每种游戏必须具有哪些规则 Mgr。
- 统一画风、调色板或素材规格。
- 所有游戏必须使用 PixiJS 或 Dialog 架构。
