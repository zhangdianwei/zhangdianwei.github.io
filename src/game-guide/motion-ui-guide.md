# 游戏动效、缓动与 UI 设计指南

本文适用于仓库内由 Vue、PixiJS 实现的小游戏。金币骑士、田园扫雷和拼图游戏是独立构建产物，只作为视觉参考，不受这里的实现约束。

动效不是装饰层。它应回答四个问题：玩家刚才操作成功了吗、什么发生了变化、变化从哪里来到哪里去、下一步应该看哪里。UI 的目标也不是把信息全部展示出来，而是让玩家在玩法压力下仍能快速看懂并操作。

## 当前项目审视

仓库已经具备两个好的基础：`game-guide` 统一了 Dialog 生命周期和清理边界，各游戏也可以拥有独立主题。现在的问题主要是缺少动效语义和组件状态规范。

| 方面 | 当前表现 | 直接影响 |
| --- | --- | --- |
| 时间系统 | 同时存在 Pixi Ticker、Tween、原生 `requestAnimationFrame`、`setTimeout` 和 CSS Transition | 暂停、销毁、降级和测试难以统一 |
| 时长 | 50、100、180、200、220、260、280、500、650、1000 毫秒等数值散落 | 相似操作的重量和节奏不一致 |
| 按钮 | 常见做法是按下瞬间缩放到 0.9、0.95 或 0.96 | 缺少过渡，0.9 的形变过强，触感忽轻忽重 |
| 缓动 | `ease`、二次曲线、三次曲线、`Back`、`Bounce` 混用 | 曲线没有表达进入、离开、反馈或奖励的区别 |
| 场景切换 | 多数界面只做整体缩放加淡入 | 缺少空间关系，所有界面像同一种弹窗 |
| 动画所有权 | `match` 中有独立帧循环和未受管的延迟调用 | 离开界面后仍可能继续更新或访问已销毁对象 |
| 帧率适配 | 部分 Ticker 动画按每帧固定增加进度 | 高低刷新率下速度不同 |
| 减弱动效 | 麻将 CSS 已处理，Pixi 游戏尚未统一处理 | 系统开启减弱动效后仍会出现大幅缩放和持续漂移 |
| UI 主题 | `ballgame` 已有语义颜色，其他游戏仍有大量界面内硬编码 | 开始、玩法、结算界面容易产生视觉割裂 |

现有实现中值得延续的部分：

- `ballgame` 的颜色角色、扩大点击区、开始页分层和连续背景已经接近可复用基线。
- `majiang` 的牌面状态、移动前后测量和 `prefers-reduced-motion` 处理可以作为 Vue 游戏参考。
- `tetris`、`game2048` 已使用 Tween 表达有限时长的状态变化，适合继续收敛动画所有权。
- `game-guide` 的 `onUpdate`、`onDeactivate`、`onDestroy` 已经提供正确的暂停和销毁位置。

## 设计优先级

动效预算按以下顺序投入：

1. 输入确认：按下、拖动、释放、命中和拒绝必须立即可见。
2. 状态解释：对象移动、数量变化、选择变化要保留因果关系。
3. 结果强调：成功、失败、升级和奖励建立清晰强弱层级。
4. 氛围运动：背景漂移、呼吸和装饰循环只在不干扰前三项时保留。

时间不足时完成前两项即可。没有明确含义的粒子、抖动和弹跳不应加入。

每个动画在实现前写出一句目的，例如“金币从拾取点飞向余额，解释余额增长”。如果只能写成“让页面更生动”，说明它还没有足够理由。

## 动效语义

### 输入反馈

反馈必须在按下的同一帧开始，不等待业务结果。它只确认“输入已收到”，不提前表示“操作已成功”。

- 按钮按下：阴影压低、亮度变化、缩放到 0.97 至 0.98。
- 可拖动物体：抬高 2 至 6 逻辑像素、加强描边或阴影。
- 不可执行操作：控件保持原位，短促改变颜色或边框，并给出原因。
- 业务处理中：保留按钮尺寸，显示忙碌状态并阻止重复触发。

### 状态变化

移动应保留空间连续性。牌从牌墙进入手牌、收集物飞向 HUD、方块进入目标格，都应该从实际来源移动到实际目标，不能在来源消失后直接在目标淡入。

布局变化优先使用前后位置插值。长距离移动的时长随距离增加，但必须限制上下界，避免麻将牌这类对象只有 220 和 650 毫秒两个突兀档位。

### 场景切换

- 同层替换使用较短的平移、交叉淡化或共享元素过渡。
- 前景 Dialog 使用遮罩加面板进入，底层画面保持位置稳定。
- 进入使用减速曲线，离开使用加速曲线，离开通常比进入短 20% 至 30%。
- 不让玩家等待装饰动画结束；关键按钮最晚在主要内容稳定时可用。

### 结果与奖励

结果界面按“结论、关键数字、明细、下一步”出现。失败也需要明确反馈，但不应使用与大奖励相同的弹跳、彩带和高亮。

奖励强度跟事件稀有度绑定：普通得分只更新数字，连续消除增加路径和短促脉冲，通关或新纪录才使用较长序列。高频事件越常见，动画越短、位移越小。

### 氛围运动

氛围动效保持低对比、低速度、低振幅，文字和关键操作附近尽量静止。连续循环不得与按钮、提示或 HUD 争夺注意力。

## 时长基线

以下数值是当前项目的起点，不是物理定律。同一游戏可以整体调整约 15%，但不要逐个文件随意修改。

| 语义 | 建议时长 | 常见用途 |
| --- | ---: | --- |
| 立即 | 0 毫秒 | 状态初始化、减弱动效下的位置变化 |
| 按压 | 60 至 90 毫秒 | 按钮按下、拖拽拾取 |
| 快速反馈 | 100 至 160 毫秒 | 释放回弹、选中、轻提示 |
| 标准变化 | 160 至 240 毫秒 | HUD 数值、列表重排、小范围移动 |
| 界面进入 | 220 至 320 毫秒 | 面板、Dialog、主要内容出现 |
| 界面离开 | 140 至 220 毫秒 | 面板关闭、对象离场 |
| 场景变化 | 280 至 420 毫秒 | 开始进入玩法、关卡切换 |
| 奖励强调 | 450 至 800 毫秒 | 通关、新纪录、稀有奖励 |

超过 800 毫秒的序列应允许点击跳过或加速完成。连续执行的常用操作不应因为动画增加等待时间。

长距离移动可以按距离计算：

```javascript
const duration = Math.min(420, Math.max(160, 140 + distance * 0.45))
```

移动的是大型面板或全屏内容时可接近上限；小棋子、图标和 HUD 数字使用下半区间。

## 缓动基线

| 语义 | CSS 曲线 | Tween 对应 | 用途 |
| --- | --- | --- | --- |
| 匀速 | `linear` | `Linear.None` | 进度、机械旋转、匀速轨迹 |
| 进入与响应 | `cubic-bezier(0, 0, .2, 1)` | `Cubic.Out` | 按钮释放、对象进入、落位 |
| 屏内移动 | `cubic-bezier(.4, 0, .2, 1)` | `Cubic.InOut` | 重排、共享元素、镜头跟随 |
| 离开 | `cubic-bezier(.4, 0, 1, 1)` | `Cubic.In` | 对象消失、Dialog 退出 |

使用规则：

- `linear` 不用于按钮、面板或对象落位，否则会显得机械。
- `Back.Out` 只用于奖励和有弹性的角色，初始状态应接近目标，例如从 0.96 到 1；不要让普通面板从 0 弹到 1。
- `Bounce.Out` 不用于常用按钮和 HUD，会拖长反馈并造成视觉噪声。
- 同一段运动只使用一条主曲线。位置和缩放可以共用曲线，透明度可以稍早完成。
- 动画中途收到新目标时，从当前视觉值继续，不先跳回旧起点。

## 位移与形变

| 层级 | 建议范围 |
| --- | ---: |
| 按压位移 | 1 至 3 逻辑像素 |
| 控件反馈 | 2 至 6 逻辑像素 |
| 小组件进入 | 6 至 16 逻辑像素 |
| 面板进入 | 16 至 32 逻辑像素 |
| 按压缩放 | 0.97 至 0.98 |
| 强调缩放 | 1.04 至 1.10 |

大面积缩放和平移更容易引发不适。优先移动局部对象，不移动整个游戏画面；需要冲击感时，先使用对象受击、短暂停顿、颜色和音效，最后才考虑屏幕抖动。

## UI 结构

### 画面层级

游戏画面固定为四层，避免玩法、特效和 UI 互相覆盖：

```text
背景与游戏世界
HUD 与常驻控件
短时反馈与特效
遮罩与前景 Dialog
```

- HUD 不跟随世界相机抖动或缩放。
- 特效层默认不接收指针事件。
- 前景 Dialog 打开后，底层停止交互，但不改变布局。
- 关键文字后方保持稳定、足够不透明的承载面，避免直接压在高对比运动背景上。

### 信息层级

- 每个界面只有一个主要任务和一个主操作。
- 玩法中先显示当前目标和紧急状态，再显示分数、关卡等次要信息。
- 同类状态固定位置，不因横竖屏改变含义；横竖屏只重排区域。
- 结算页先给胜负或成绩，再给分项数据，最后给继续或重试。
- 教学提示靠近对应对象，在玩家完成动作后立即消失。

### 视觉令牌

每个游戏在自己的 `theme.js` 中定义语义角色，不在各 Dialog 中散落颜色和字号：

```javascript
export const theme = {
  color: {
    background: 0x0b1020,
    surface: 0x151d31,
    surfaceRaised: 0x202b43,
    text: 0xf7fbff,
    muted: 0x9cabc2,
    primary: 0x4dd8ff,
    reward: 0xffd447,
    danger: 0xff5f6d,
    focus: 0xffffff,
  },
  space: { xs: 4, sm: 8, md: 16, lg: 24, xl: 32 },
  radius: { control: 6, panel: 8 },
  motion: { press: 80, fast: 140, standard: 200, enter: 260, exit: 180, reward: 600 },
}
```

令牌属于具体游戏，`game-guide` 只规定角色名称和行为语义，不强制所有游戏使用同一套画风。

### 排版与间距

- 延续仓库的 8 像素间距节奏，微调只使用 4 像素。
- 面板圆角保持 6 至 8 像素，像素风游戏可使用直角。
- 一个界面控制在标题、正文或 HUD、辅助文字三个文字层级。
- 不通过“字号先放大一倍、父容器再缩小一半”实现适配，直接使用最终逻辑尺寸。
- 数字列使用固定宽度或等宽数字，避免分数变化推动周围布局。
- 文本、按钮、棋盘、计数器都设置稳定尺寸，动态内容不能改变整体排版。

Vue 界面已集成 View UI Plus 时，按钮、图标按钮、弹窗、开关和提示优先使用默认组件。Pixi 场景中的游戏内控件可以自绘，但必须保持相同的状态完整性。

## 组件状态

### 按钮

按钮至少包含以下状态：

| 状态 | 表现 |
| --- | --- |
| 可用 | 主操作有明确填充色，次操作降低层级 |
| 悬停 | 亮度或描边轻微变化，不改变尺寸 |
| 按下 | 阴影压低，缩放到 0.97 至 0.98 |
| 键盘聚焦 | 独立焦点环，不能只依赖悬停色 |
| 禁用 | 降低对比并关闭交互，文字仍可辨认 |
| 处理中 | 尺寸不变，阻止重复提交，保留进度反馈 |

屏幕上的实际触摸区域至少为 44×44 CSS 像素。Pixi 逻辑尺寸经过画布缩放后仍要满足这一要求，可以用 `hitArea` 扩大热区，但不要让相邻热区重叠。

业务动作在 `pointertap` 或 `click` 触发，`pointerdown` 只播放按压反馈。必须处理 `pointerupoutside` 和 `pointercancel`，避免按钮停留在按下状态。

### 选择项与牌块

- 悬停用于预览，选中使用位置加描边，禁用不能只靠降低透明度。
- 选中位移保持 4 至 8 像素，不能遮住相邻项的重要信息。
- 拖动时原位置保留占位，避免列表瞬间回流。
- 落位后再恢复阴影和层级，形成拾取、移动、落下三段反馈。

### HUD 数字

数值变化先保证最终值准确，再做插值。小变化滚动 120 至 200 毫秒；大变化可以限制滚动时长并在结尾脉冲一次，不能按差值逐个数字慢慢播放。

收集类游戏采用“来源对象飞向 HUD、图标短促脉冲、数字更新”的顺序。飞行对象只用于解释来源，不要为每个粒子都创建昂贵的文字或 Graphics。

### Dialog

推荐进入序列：

1. 遮罩在 120 至 180 毫秒内淡入。
2. 面板从下方 16 至 24 像素进入，持续 220 至 280 毫秒。
3. 标题、关键数字、操作区按 30 至 50 毫秒间隔出现。
4. 主操作在面板稳定时可用，不等待装饰动画。

退出顺序反向，但不需要逐项等待，整体控制在 140 至 220 毫秒。

### 失败、伤害与拒绝

- 玩法对象先产生受击变化，HUD 后更新，避免只抖整个屏幕。
- 短暂停顿控制在 30 至 60 毫秒，只用于低频强冲击事件。
- 屏幕抖动振幅小于核心对象尺寸的 3%，持续 80 至 160 毫秒，并提供关闭或强度设置。
- 错误提示使用颜色、图形和文字中的至少两种渠道，不只闪红一下。

## PixiJS 实现约束

### 每个游戏只保留一个动画时钟

- 持续运动写在 Dialog 的 `onUpdate(delta)` 中。
- 有限时长的属性插值使用当前依赖 `@tweenjs/tween.js`。
- 不在 Pixi 显示对象或 Mgr 内另起原生 `requestAnimationFrame` 循环。
- 不按帧固定增加进度，使用 Ticker 的时间差或 Tween 的时间源。
- 动画暂停、覆盖和销毁服从所属 Dialog 生命周期。

有限动画由所属 Dialog 持有独立 Tween Group：

```javascript
import * as TWEEN from '@tweenjs/tween.js'

onCreate() {
  this.tweens = new TWEEN.Group()
  this.motionTime = 0
}

onUpdate(delta) {
  this.motionTime += delta * 1000 / 60
  this.tweens.update(this.motionTime)
}

onDestroy() {
  this.tweens.removeAll()
}

animate(target) {
  return new TWEEN.Tween(target, this.tweens)
    .to({ alpha: 1 }, 200)
    .easing(TWEEN.Easing.Cubic.Out)
    .start(this.motionTime)
}
```

这里的时间只在 Dialog 激活期间累积，因此被覆盖时动画真正暂停，销毁时也不会继续回调。不要把所有界面的 Tween 更新放在 App 级全局循环中。

### 性能

- 动画优先修改 `position`、`scale`、`rotation`、`alpha` 和 `tint`。
- 不在每帧重画不变的 Graphics，也不在每帧修改 `PIXI.Text.text`。
- 高频粒子复用 Sprite 或对象池，限制同时存在数量。
- 粒子、滤镜、阴影和屏幕抖动按事件重要度分配，不同时全开。
- 动画目标销毁前停止 Tween，回调中检查 Dialog 是否仍存在。

## Vue 与 CSS 实现约束

- 简单控件状态和 DOM 进入离开优先 CSS Transition。
- 列表或牌面跨区域移动使用前后布局测量，时长按距离限制在 160 至 420 毫秒。
- 优先动画 `transform` 和 `opacity`，避免连续修改布局属性。
- `ResizeObserver` 触发的纯布局适配不播放动画。
- 离开组件时清理计时器、观察器和帧请求。

```css
.control {
  transition: transform 80ms cubic-bezier(0, 0, .2, 1),
    filter 80ms cubic-bezier(0, 0, .2, 1);
}

.control:active {
  transform: scale(.98);
  filter: brightness(.94);
}

@media (prefers-reduced-motion: reduce) {
  .control {
    transition-duration: 0ms;
  }
}
```

## 减弱动效

减弱动效不是关闭所有反馈，而是去掉大范围位移、缩放、循环和镜头运动，同时保留颜色、描边、透明度和最终状态。

| 原效果 | 减弱后 |
| --- | --- |
| 面板缩放加位移 | 100 至 160 毫秒淡入 |
| 收集物长距离飞行 | 来源短闪，HUD 直接脉冲 |
| 屏幕抖动 | 受击对象变色或描边 |
| 背景持续漂移 | 静态背景 |
| 彩带和粒子雨 | 短促局部高亮 |
| 数字逐步滚动 | 直接更新并淡化强调 |

Pixi 游戏启动时读取系统设置，并允许游戏内设置覆盖：

```javascript
const systemReduced = matchMedia('(prefers-reduced-motion: reduce)').matches
const reducedMotion = savedSetting ?? systemReduced
```

设置为减弱后，关键交互仍必须有非运动反馈。任何自动开始、持续超过五秒且与正文或菜单同时出现的装饰运动，都应能暂停、停止或隐藏。

## 改造顺序

### 第一阶段：统一基础反馈

1. 为每个游戏补齐 `theme` 的颜色、间距、圆角和动效令牌。
2. 统一按钮状态，移除 0.9 的强缩放和瞬间跳变。
3. 将业务动作从 `pointerdown` 移到 `pointertap`，补齐取消和移出处理。
4. 为 Pixi 游戏接入减弱动效设置。

### 第二阶段：统一动画所有权

1. `match` 移除独立帧循环和按帧累加进度，纳入 Ticker 或 Dialog Tween Group。
2. `tetris`、`game2048` 将全局 Tween 更新下沉到所属 Dialog。
3. 所有延迟、序列和 Tween 在 Dialog 销毁时取消。
4. 连续动画只保留一套时间源。

### 第三阶段：重做关键流程

按“开始页、第一次操作、核心成功反馈、失败、结算、重试”逐条重做，不先处理低频边角页面。

| 项目 | 优先改造点 |
| --- | --- |
| `game2048` | 开始和结算的缩放幅度、统一字体与主题、收集到排名或分数的因果反馈 |
| `tank2` | HUD 信息层级、按钮完整状态、出生和受击反馈、降低黑色空区的割裂感 |
| `tetris` | 标题持续摆动、按钮按压、消行和连击反馈、结算信息顺序 |
| `match` | 动画生命周期、帧率无关时长、结算序列、按钮触发时机 |
| `ballgame` | 将现有开始页风格延续到玩法和结算，增加 Pixi 减弱动效 |
| `majiang` | 将两档移动时长改为距离映射，补齐聚焦态，降低长距离发牌时间 |

## 验收清单

- 按下控件的同一帧出现反馈，业务动作只触发一次。
- 相同语义使用相同的时长、曲线、位移和声音强度。
- 进入、屏内移动、离开使用符合方向的缓动。
- 常用操作不等待装饰动画完成。
- 动画中途收到新状态时从当前视觉值继续。
- 横竖屏切换不播放无意义的全场移动。
- Dialog 被覆盖时动画和输入暂停，销毁后没有回调继续执行。
- 30、60、120Hz 下动画时长接近一致。
- 低性能移动设备上没有持续掉帧，粒子和滤镜可降级。
- 系统开启减弱动效后没有大范围缩放、持续漂移或屏幕抖动。
- 关闭声音后，结果和错误仍能通过视觉理解；减弱动效后也不丢失信息。
- 按钮、牌块和 HUD 动态内容不会改变容器尺寸或推动布局。
- 开始、玩法、结算使用同一主题角色和文字层级。
- 每个界面有明确主任务，结算页有明确下一步。
